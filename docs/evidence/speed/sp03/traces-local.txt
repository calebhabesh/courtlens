1. What one intent prefetch sends (hover on a Stats row, /players/1629029?season=2026-27&from=stats)
   Captured from the browser, then replayed twice each with the same headers, counting API cache hits+misses:

   request                                             headers                                     bytes    time     API reads
   /players/1629029?season=2026-27&from=stats&_rsc=..  rsc, next-router-prefetch, segment /_tree     341 B   2.0-2.8 ms   0
   /players/1629029?season=2026-27&from=stats&_rsc=..  rsc (no prefetch header): the page render  288,309 B  8.8-11.3 ms  9 (all hits)
   /players/1629029?_rsc=..                            rsc, next-router-prefetch, segment /_tree     315 B   1.8-1.9 ms   0

   So a full prefetch costs the server one page render (the same request a click makes) plus one or two
   route-tree lookups that read nothing. The header's /stats link sends one tree lookup and one render.

2. Click after a prefetch: no RSC request and no document (fixture and real data alike). The click renders from
   the router's copy. A page that was loaded as a document is kept by the router too: starting on /stats, a hover
   on the header's Stats link sends nothing and the click after it sends nothing.
