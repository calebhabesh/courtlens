# Databallr replica: free-source feasibility

Checked **2026-10-01** for the UI/capability planning interview. This is source research, not data admission or a completed ingestion milestone. Existing app files and dirty work were preserved. Only this note was written.

Subsequent owner decisions: versioned financial CSV imports/manual corrections and genuine lightweight Live updates were accepted after this investigation. Earlier references below to a pending owner decision describe the inspection-time proposal; use the [replica handoff](../databallr-replica-implementation-plan.md) for current requirements.

Read the existing [workbench source findings](workbench-source-findings.md) and [zero-cost source research](zero-cost-data-sources.md). New checks read primary documentation, public pages, bounded GitHub release metadata and four ordinary unauthenticated live-endpoint responses. JSON responses were inspected in memory without retention; no bulk datasets were downloaded, ingestion/reliability spike run, account created, payment made or person contacted. Asset existence and schema documentation do not prove completeness, reproducible parsing, permitted redistribution or reliable refresh.

## Feasibility classification

**A** means a concrete public file candidate is verified in release metadata, or earlier local research records successful acquisition. It does **not** mean admitted. **B** means publicly visible/free-access functionality exists but automated access, coverage, identity or reuse remains unresolved. **C** means proprietary or no verified free dependency was found. Classes apply to capabilities, not an entire provider.

## Source gates for implementation blocks

1. **Inventory and rights:** Pin repository revisions and observed files; retain URL, source namespace, acquisition time, bytes, hashes, schema/parser version and attribution. SportsDataverse declares CC BY 4.0 for data and MIT for helper code; the alternative archive declares Apache 2.0. These labels do not independently prove all upstream rights or authorize every use. Record local use versus public redistribution separately. [SportsDataverse package declaration](https://raw.githubusercontent.com/sportsdataverse/sportsdataverse-data/main/DESCRIPTION), [code license](https://raw.githubusercontent.com/sportsdataverse/sportsdataverse-data/main/LICENSE), [archive license](https://github.com/shufinskiy/nba_data/blob/main/LICENSE), [NBA terms](https://www.nba.com/termsofuse)
2. **Identity and temporal coverage:** Normalize ten-character NBA game IDs; preserve NBA versus ESPN namespaces; map seasons/phases explicitly. Produce expected/observed/excluded games by capability, not a single success flag. Historical schedule reconstruction and latest downloaded external ratings are not historical knowledge available at issuance.
3. **PBP/lineup admission:** Reconstruct and reconcile one documented season before expanding scope. Specify event order, starter overrides, substitutions, simultaneous events, overtime, free throws, technical fouls, offensive rebounds and possession attribution. Hash transformation/override versions and retain every rejected game. Do not reuse a season summary as arbitrary cutoff evidence.
4. **Shots/matchups admission:** Reconcile attempt/make totals and joins; distinguish unrecorded coordinates from zero, verify court geometry and matchup denominators. Publish descriptive limitations and sample thresholds alongside metric definitions.
5. **Current refresh and live status:** Observe changed source assets and finalized games on distinct in-season dates; exercise corrections, timeouts, stale data and last-good-release retention. A separate live gate must observe actual scheduled/in-progress/final transitions, clock/stat changes, source/acquisition times and final reconciliation. Keep provisional observations apart from admitted finalized research releases. CourtLoad currently disables 2027 player/team acquisition in its source config; turning on a worker does not close this gap.
6. **External estimates:** Admit DARKO only after retrieving a legitimate export, proving entity/date mappings and documenting rights/version provenance. Mark it external and predictive. Keep unavailable proprietary fields absent rather than filling them with locally invented equivalents.
7. **Financial/fallback contract:** Retained admitted historical data and explicit user imports can support useful research while individual current/extended capabilities are unavailable. Decide the financial field scope and whether an owner-supplied CSV is acceptable before promising salary features; do not infer contract expiration or free agency from blank amounts. No trial, purchase, access-control bypass or vendor subscription is a prerequisite for core operation. Authenticated commercial providers such as [Sportradar](https://developer.sportradar.com/basketball/reference/nba-overview) do not satisfy an unverified free dependency merely because their documentation is public.

Planning inference: a no-paid-dependency expansion to historical shots, lineups, on/off and descriptive WOWY has credible concrete source candidates. Matching every Databallr field, fresh current coverage, vendor ShotQuality, complete contract intelligence and locally reproduced DARKO are not established by this research. Each independently admitted capability should decide which tools the app can honestly offer.
