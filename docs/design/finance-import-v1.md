# B28 financial source-book admission v1

This is a local operator CSV/document import policy, separate from basketball releases and B29 numerical operations. Automation, comprehensive salaries, present free-agent coverage and model-to-money conversions are not established by admission of a bounded book.

`courtload finance-template PATH` writes an exclusive header. A bundle contains `observations.csv`, `manifest.json`, and `sources/<sha256>` retained evidence bytes. `finance-preview BUNDLE` validates without writes; `finance-import BUNDLE --execute-now` stages content-addressed bytes, creates an allowlisted tracked worker job and executes under the existing coordinated lock. Omit `--execute-now` to queue for the worker. The existing jobs API keeps its operator-token boundary; jobs receive only a staged hash, never an arbitrary input pathname. `finance-verify RELEASE_ID` checks retained bytes, identities and membership reconciliation. Source access is never initiated by a financial result read.

## Admission

- Exact template columns are defined by `FinanceRow` in `domain/finance.py`. UTF-8 CSV maximum 2 MB / 5,000 rows, strict headers/row widths, no spreadsheet formulas. No floating-point money; USD decimal strings have at most two decimals and become integer cents. Zero and blank remain distinct. Seasonal amounts require consecutive YYYY-YY; contract total/guaranteed total can have unknown season. No equal annual allocation of a multi-year total.
- Contract, amount, option, guarantee, status and association are independent observation families. Their typed nullable terms live in each immutable payload; family-inappropriate fields reject. Source namespace/entity and canonical NBA ID are explicit, with a separately retained mapping note and an existing NBA identity FK. Direct NBA IDs must agree exactly; other mappings require reviewed crosswalk evidence. Names cannot resolve mappings. Canonical team IDs come from the NBA team catalog and never from current or last-season participation.
- A manifest pins all input bytes, source URL, attribution/use basis, actual timezone-aware observation and source-note/document locator. Notes are labelled notes, not claimed full-page captures or reuse permission. Announced times and contract effective dates remain unknown when not documented. A source published in 2025 but acquired in 2026 is a retrospective observation; acquisition cannot manufacture a 2025 known-at boundary. Association rows require an explicit dated source association, and do not establish current roster membership or contract start date.
- Status taxonomy is `unknown_review`, `unsigned`, `signed`, `returned`, `option_pending`, `two_way`. Rows are observations in a declared source scope, not inferred current market categories. A historical extension signing is labelled as such. Unknown terms do not imply expiration/unsigned. Unknown option/guarantee labels remain null; unexercised options remain observations, not realized future outcomes.

## Books and corrections

Four additive tables hold books, retained source bytes, independently typed observations and exact selected membership. PostgreSQL rejects UPDATE/DELETE/TRUNCATE and membership additions after the admission transaction. ORM writes reject mutations too. The public basketball pointer is independent. Full original CSV and document/note bytes are stored in the database, so ordinary database backups retain them without relying on external worker staging files.

An initial book has no parent. A subsequent book names its parent and imports reviewed additions/corrections; all unchanged selected observations retain their original IDs. Duplicate player/contract/season/family/amount-kind grains reject, even across providers. A conflicting grain needs `supersedes_id` matching the selected parent observation, a reason and supporting source bytes. Corrections cannot precede originals, change semantic grain, or silently rewrite retained terms. Both alternatives survive; only the explicit reviewed descendant enters its book's selected membership. This initial policy intentionally rejects unresolved overlapping alternatives instead of choosing a provider automatically. It also permits branches; B29 must require an explicit book rather than assume newest means authoritative.

The entire selected book remains bounded to 5,000 rows; sources are bounded to 100 entries / 20 MB total. Identical manifest/parser imports reuse their book. No release publication, financial thresholds, salary sums, modeled value or public mutation UI belongs to this block. B29 must preserve known-at/effective filtering, unknown dates, inherited source provenance and independent basketball context. Full restore acceptance remains an integration gate beyond focused byte/membership verification.
